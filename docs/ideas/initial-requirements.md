# 初期アイデア: 社内AIイベント ロゴ投票アプリ

> 出典: `idea_book.md`（要件の詳細）, `setup_guide.md`（Supabaseセットアップ手順）

## 課題

社内AIイベントのアイスブレイクとして「ロゴ作成大会」を開催するにあたり、大人数（最大200名程度）が参加する投票を、手間なく・公平に・楽しく実施する仕組みがない。
- 100〜200枚規模の画像を単純な一覧やリストで見せると、表示順によって有利不利が生まれる
- 同僚の作品に対して「Dislike」を明示することへの心理的な抵抗感がある
- 認証機能を作り込む時間はなく、社内イベント用のワンショットなシステムとして手早く用意したい

## ターゲット

- **参加者**: 社内メンバー（最大200名程度）、社員用スマートフォンのブラウザからアクセス
- **運営**: イベント当日に結果発表画面をスクリーンに映し、優勝者を発表する担当者
- アクセス制御は行わず、URLを知っていれば誰でも参加できる想定（機密情報は扱わない前提）

## 主要機能（コア体験）

アプリは **投稿フェーズ → 投票フェーズ** の2つのフェーズに明確に分ける（投稿締切後に投票を開始する運用とし、投稿受付中の画像が投票側に見切れて混在しないようにする）。

1. **トップ画面**: イベント概要と「画像を投稿する」「投票へ進む」の2導線
2. **画像アップロード**: ロゴ画像・投稿者名・一口メモ（すべて必須）を投稿。1人が複数点投稿してもよい。投稿者名は運営の管理者画面でのみ表示し、投票画面では匿名化する
3. **スワイプ式1次選考（Tinder風UI）**: 画像と一口メモをランダム順に1枚ずつ表示し、右スワイプ（キープ）／左スワイプ（次へ）で仕分け。表示順による有利不利をなくし、「Dislikeする罪悪感」を「キープして温存する」という前向きな行動に置き換える。最低1枚はキープしないと決選投票に進めない
4. **最終投票（決選投票）**: 1次選考でキープした画像だけをグリッド表示し、その中から**上位3つまで**選んで投票（自分の投稿への自己投票も可）
5. **結果発表（管理者画面）**: 得票数順のランキングで画像・一口メモ・投稿者の本名を表示し、イベント当日にスクリーン投影して発表。事前アクセスによるネタバレを防ぐため、簡易パスワードで保護する

## 詳細仕様（決定事項）

- **不正投票対策**: 厳密なユーザー認証は行わないが、Cookie/localStorageベースの匿名ID（ブラウザ発行のランダムID）を用いて「1端末1票（決選投票は1端末につき最大3作品まで）」を軽く制御する
- **1次選考の状態管理**: MVPでは localStorage のみに保持し、サーバー側には保存しない。ブラウザを閉じる／キャッシュを消すと選考はやり直しになる仕様で割り切る（再開可能にする実装は将来検討）
- **同数得票時のタイブレーク**: 同数となった作品同士で再度決選投票（ランオフ）を行う
- **データ保持期間**: 特に定めない（イベント終了後の自動削除は行わない）
- **画像アップロード制限**: ファイルサイズ上限10MB、形式は jpg/png/heic/webp を許可（確定）

## 演出・UXアイデア

- スワイプ操作（キープ／次へ）に効果音やアニメーション（confetti等）を付け、Tinder風の楽しさを演出する
- 1次選考中に「あと◯枚」の進捗バーを表示する
- アプリURLをQRコードで配布できるようにする（会場での案内をスムーズにする）

## MVPスコープ

- 投稿フェーズ／投票フェーズの分離
- 画像アップロード（投稿者名・一口メモ含む、1人複数点可）
- スワイプ式1次選考UI（ランダム表示、右/左スワイプ、localStorage保存、最低1枚キープ必須）
- 決選投票（キープした画像から上位3つまで選択、自己投票可）
- 匿名IDベースの簡易的な多重投票防止
- 管理者用の結果発表画面（ランキング表示、投稿者名開示、簡易パスワード保護）
- スワイプ演出・進捗バー・QRコード配布

MVP対象外（将来的な検討事項）:
- 本格的なユーザー認証
- 1次選考状態のサーバー保存・再開機能
- 投稿の編集・削除機能
- イベント終了後のデータ自動削除ポリシー

## 技術的な前提（開発方針）

- **開発ツール**: Claude Code
- **フロントエンド**: Next.js (App Router), Tailwind CSS
- **バックエンド/ストレージ**: Supabase（Database & Storage、無料枠で運用）
- **スワイプUI実装**: `react-tinder-card` または `framer-motion`
- **データベース設計イメージ**:
  - `logos` テーブル: `id`, `image_url`, `uploader_name`, `memo`, `created_at`
  - `votes` テーブル: `id`, `logo_id` (FK -> logos.id), `voter_anon_id`（匿名ID、多重投票防止に使用）, `created_at`
  - 1次選考のキープ状態はサーバーDBには持たず、クライアント（localStorage）のみで管理
- Supabaseのプロジェクト作成・APIキー取得手順は `setup_guide.md` を参照（Project URL・anon API keyの取得が前提条件）
