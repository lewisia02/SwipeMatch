# 横断整合性チェックスキル

`docs/`配下の7つの永続ドキュメント(product-requirements.md / functional-design.md / ui-design.md / architecture.md / repository-structure.md / development-guidelines.md / glossary.md)とCLAUDE.mdは、互いに用語・数値・仕様を参照し合っている。1つのドキュメントを編集しても、他のドキュメントへの波及は自動的には検出されない。このスキルは、その波及を安価に検出するための「概念マップ」ベースの横断チェックを行う。

## 背景: なぜこのスキルが必要か

各ドキュメント作成スキル(prd-writing / functional-design / ui-design / architecture-design / repository-structure / development-guidelines / glossary-creation)は、それぞれ担当する1ドキュメントの品質にのみ責任を持つ。上流ドキュメント(PRD等)との整合性はチェックするが、自分の変更が影響する**下流**ドキュメントへの反映までは行わない。このスキルはその隙間を埋める。

## 概念マップ

`.claude/skills/consistency-check/concept-map.md` に、プロジェクト内の横断的な概念と、それが登場する全ドキュメントの一覧を維持している。このマップは一度作って終わりではなく、**チェックのたびに更新し続ける生きたドキュメント**である。

## モードA: 差分チェック(デフォルト・推奨・低コスト)

ドキュメントを編集した直後、または `/check-consistency` を引数なしで実行したときに使う。

1. 直近の変更内容を確認する(未コミットのdiffがあれば `git diff`、無ければ直前の会話で編集した内容を思い出す)
2. `concept-map.md` を読み込み、変更内容に登場するキーワードが概念マップのどの行にマッチするか特定する
3. マッチした概念ごとに、概念マップに列挙されている「影響するドキュメント」を `Grep` で検索し、変更後の記述と食い違っていないかを `Read` で確認する
4. 変更内容が概念マップに載っていない新しい横断的概念(複数ドキュメントにまたがりそうな用語・数値・仕様)を含む場合は、`concept-map.md` に新しい行を追記する(既知の登場ドキュメントだけでよく、完全な網羅は不要)
5. 不整合が見つかった場合は箇条書きで報告し、ユーザーに修正してよいか確認してから `Edit` で直す
6. 不整合がなければ「概念マップ上でX件チェックし、不整合なし」と簡潔に報告する

**コスト目安**: サブエージェントを起動せず、Grep/Readのみで完結させる。1回のチェックで数千〜1万トークン程度に収める。

## モードB: 全体スイープ(オプション・高コスト・任意実行)

用語集の棚卸しや大きなマイルストーン後など、徹底的に確認したいときのみ使う。7ドキュメントそれぞれに対して `doc-reviewer` サブエージェント(`/review-docs` と同じ方式)で相互レビューを行う。**実行前に必ずユーザーに確認する**(数万トークン規模のコストがかかるため)。

## 引数(`/check-consistency` 経由の場合)

- 引数なし: モードAを、直近の変更(git diffまたは会話履歴)に対して実行
- ドキュメントパスを指定: そのドキュメントに登場する概念を概念マップから逆引きし、関連ドキュメントとの整合性をモードAと同じ要領で確認
- `--full`: モードB(全体スイープ)の実行をユーザーに確認する

## 出力フォーマット

```markdown
## 横断整合性チェック結果

対象: [直近の変更 / ドキュメントパス]
チェックした概念: [概念マップから該当した概念のリスト]

### 不整合

1. [概念名]: [ファイルA]の記述 vs [ファイルB]の記述 が食い違っている(優先度: 高/中/低)

### 概念マップへの追記

- [新しく検出した概念]: 登場ドキュメント [リスト]

### 結論

- 不整合 [N] 件 / 新規概念 [M] 件をマップに追加
```

## 注意事項

- このスキルは「発見」までを担う。実際の修正はユーザーに確認してから行う(過去のドキュメントレビューと同じ運用)
- 概念マップの網羅性がチェックの精度を左右する。新しい横断的概念を見つけたら必ずマップに追記すること
- `docs/ideas/initial-requirements.md` は下書き・ブレインストーミング成果物であり、正式ドキュメントとの厳密な同期は不要(CLAUDE.md「ドキュメント管理の原則」参照)。整合性チェックの対象外としてよい
